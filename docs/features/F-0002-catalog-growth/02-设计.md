# 扩充与入口设计

## 方案比较

1. 只追加数据与 Topics：成本低，但读者仍难找到能运行、能下载的产物，也难分享筛选后的主题集合。
2. 保留静态站，增加材料筛选、可分享的筛选 URL、英文 README、入门路线与自动生成的新增目录：沿用现有架构，直接改善使用和传播路径。采用。
3. 全站多语言、账户、订阅与行为分析服务：维护和隐私成本较高，目前没有足够数据证明需要。暂不采用。

## 产品与数据

保留黑底蓝色的作品档案布局。类型筛选旁增加“有源码 / 有演示入口 / 完整视频”材料条件，可与作者、类别和来源交集。演示入口仅表示作者提供链接，不承诺每个站无需登录或已经独立试玩。URL 保存当前筛选，复制集合链接后应能恢复相同结果；未知参数忽略，不覆盖传播用的 UTM 参数。

增加稳定收录日期字段 `addedAt`，旧条目为 2026-09-06，新条目为 2026-09-07。它与作品原始发布日期、核查日期各自独立；“最新收录”按入库日期排序，不伪装成刚发布作品。

材料不完整时保持 null。纯报告仓库不标为源码。数量和最新收录日期从数据生成，避免 README、网站与目录长期漂移。维护英文摘要入口，不声称整站已完成多语言。

## 传播与测量

README 头部加入英文切换、入门与更新入口。推广稿指向主题集合，UTM 仅用于预留来源标记；当前无统计后端，不能用参数直接声称已经能衡量各渠道转化。

完善根页标题、描述、canonical、robots 和 sitemap；它们帮助声明页面含义和规范地址，不保证收录或排名。不生成未被明确要求的社交预览图。

## 风险与回滚

不自动向外部社区发帖，不把作者公开展示当独立复现，不将改写提示词当原文。媒体沿用 GitHub Release；每个新文件校验完整时长、字节与 SHA-256，较小播放版本避免增加不必要的页面下载负担。数据、入口与文档作为相干提交，出错时可回退 Git 版本与静态发布。
