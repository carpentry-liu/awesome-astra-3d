# 设计

## 范围

1. 真实链接编码资源、分组、排序，普通点击与新标签/复制地址一致，保留语言及 UTM。
2. 稳定六件编辑精选与最新收录分开；三条材料上手路径、四个任务专题、明确 GitHub Star 收藏入口。
3. 中文默认，英文导航/筛选/标题可切换；来源原文与未翻译说明保持原语言，不伪造译文或提示词。
4. 初始目录使用轻量索引，首批 36 条；详情逐件按需取 JSON，保留旧 #case= 深链接。搜索仍覆盖全部数据中的原有搜索字段。
5. 所有记录生成静态 /cases/<id>/ 详情页，真实卡片 href；各页标题、canonical、OG/Twitter 封面、来源、材料、原始日期与证据。四个专题页及目录分批链接可抓取，避免缩短首页导致其余作品不可发现。
6. README 中英入口、精选和截图同步；上手文档保留原有资料并把第一步置顶。准备仓库内分享素材与衡量说明，不发送外部帖子。

## 方案比较

A. Vinext 动态路由 generateStaticParams：组件复用好，但 beta 静态导出与 GitHub 子路径需新增路由验证。

B. 构建时从事实源生成独立静态 HTML：目录与详情可直接抓取、无需新增依赖，不影响现有 Vinext 首页；少量展示模板需单独维护。

采用 B。所有生成逻辑集中脚本，HTML 转义、URL 来源与子路径统一处理，导出检查覆盖每页、metadata 和资源。首页保留交互弹窗；真实链接作为渐进增强和分享地址。单条 JSON 由 catalog 生成到忽略的 public/case-data/，构建复制到导出；轻量索引可追踪且用测试校验与事实源一致。

## 视觉与约束

延续墨黑、亮蓝、大图与细边框的作品档案馆风格。稳定精选六件覆盖不同产物，不随日更自动替换。移动端减少首屏非必要内容但保留完整入口。无弹窗催 Star，无新增分析 SDK，无第三方工程执行，无新媒体下载，无模型 API 调用。

工程入口意味着作者公开材料，不能统一称为已经复现；完整视频保持原帖全部时长，保留原作者权利。历史链接失败记录保留日期，不把今日 HTTP 200 当作完成试玩。

## 验收与回滚

检查、lint、构建通过；真实浏览器测试修改键资源链接、英文、筛选/清除、按需详情、旧 hash、静态详情、目录下一批、手机和控制台；GitHub Pages 子路径校验、部署后作品 metadata 与媒体地址验证。截图写 docs/media，README 引用真实生产构建截图。

只发布 GitHub Pages；用户已明确无需部署 ChatGPT/Sites，优先于 R-0002 旧双部署文字。按一个相干提交回滚功能及同版生成物。
