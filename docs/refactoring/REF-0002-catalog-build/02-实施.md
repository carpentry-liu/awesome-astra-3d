# 实施

- **首次启动**：在仅含基线 Git 文件的副本运行 README 的开发命令，`/case-data/teddy-rooftop-laundry.json` 返回 HTML 404。`predev` 现在和生产构建共用 `prepareCatalog`；先检查所有 ID，再更新索引、完整 JSON 和单条详情。重复或不安全的 ID 不会删掉上次生成的详情。只改一件作品时，其余作品文件不重写，避免触发数百次开发服务器刷新。
- **仓库分层**：从原静态生成脚本提取双语文案、HTML 模板、路由和 sitemap。专题清单移入 `data/topics.json`，浏览器的静态媒体回退脚本与样式并排放在 `public/`。原脚本仍支持单独生成、`--sitemap-only` 和既有导出函数。视频校验无需导入渲染器。首页、README 生成和静态构建共用站点配置。
- **完整录像**：临时文件与最终 MP4 位于同一目录。仅在完整读取、字节数与 SHA-256 均通过后更名；异常流和校验失败清理本次临时文件，保留已有播放文件。归档 URL、发布目录和媒体内容没有变化。
- **贡献检查**：PR 和发布共用同一套检查与 Pages 构建。PR 的令牌只有读取仓库权限，跳过视频下载、构件上传和部署；部署任务才持有 Pages 写权限。生成后检查工作树差异；README 自动区块缺少或重复标记会明确报错，标题中的美元符号按原文写入。

Git 属性按 [GitHub 的生成文件规则](https://docs.github.com/en/repositories/working-with-files/managing-files/customizing-how-changed-files-appear-on-github) 标出五个受控产物，案例事实、专题和双语 README 仍默认显示完整差异。单独固定媒体回退脚本的 LF 行尾，保持 Windows 检出与原模板字符串生成的字节一致。

没有新增运行依赖。四个专题的名称、作品顺序、全部案例及既有公开链接保持不变。完整结果见[验证记录](03-验证.md)。
