# 案例库生成与发布审查

基线为 2026-10-31 的 `c02a817`。保留首页、旧分享链接、两种语言的静态页、公开 JSON、原作者链接及全部录像地址。此次调整的是贡献者从修改数据到发布网站的路径。

| 审查发现 | 处理与验收 |
| --- | --- |
| README 的首次启动流程没有生成被 Git 忽略的单条 JSON，首页能打开，点开作品却读不到详情 | 开发和生产复用同一套数据生成代码；用干净目录验证首次启动 |
| 专题内容、双语文案、路由、HTML 和文件写入都在一个脚本中；视频校验只为站点地址也要导入整套模板 | 将专题移到数据目录，分离模板和路由，保留现有 CLI 与所有公开路径；逐文件比较改动前后导出 |
| GitHub 只在推送 main 后检查。构建自动重写派生文件，可能掩盖 PR 遗漏的 README、索引或目录变动 | PR 运行只读检查和 Pages 构建，并检查受 Git 跟踪的生成结果。媒体归档下载及部署仍仅用于发布 |
| 完整录像直接写入最终 MP4，网络中断会留下看似可用的残片 | 下载到同目录临时文件，长度和 SHA-256 都通过才替换。用截断响应、校验失败和成功下载复测 |

参考 [Awesome Selfhosted Data 的 PR 检查](https://github.com/awesome-selfhosted/awesome-selfhosted-data/blob/master/.github/workflows/pull-request.yml) 和 [Eleventy Base Blog 的内容与模板分层](https://github.com/11ty/eleventy-base-blog#implementation-notes)。选择调整现有生成流程；整站迁移框架或改成多包仓库会增加部署和 URL 回归风险，不能解决上述问题。无新增依赖、不移动公开资源。修改可通过还原本次 Git 差异回滚。
