# 仓库审查与清理方案

## 问题与范围

2026-10-08，基于干净的 `e9f3a2d` 审查代码、导入闭包、依赖、构建与文件引用。清理前有 313 个受 Git 跟踪的文件（21,697,142 字节），其中大量 UI 模板没有消费者，114 张旧截图占 16,255,102 字节。`npm start` 仍指向没有生成的 Cloudflare Worker 配置；文档入口被每日实施日志淹没。

保留案例事实、原作者与证据、完整媒体清单、当前四张 README 截图、分享封面、贡献入口和双语静态页面契约。清理对象仅限本仓库确认无用的受控文件及对应依赖；不修改 Git 历史，不改第三方作品，不提交本地迁移材料。

## 两种方案

1. 只删没有导入的模板和直接依赖，保留历史文档及截图。风险低，但大部分体积与目录噪声继续存在，失效的启动配置仍影响贡献者。
2. 依据引用关系删除模板、弃用托管配置与旧截图，将仍有效的架构决策、收录/下架规范及维护流程归并到长期文档，再删除重复阶段日志。修复审查确认的行为缺陷，并验证完整发布链路。采用此方案：当前消费者可追溯，旧文件仍可从 Git 历史恢复。

## 实施边界

- 网站实际使用的 Input、Tabs、Dialog 及依赖保留；仅删除无消费者的 UI 文件和导出。
- 使用现有 Vite 预览静态产物，移除 Sites/Cloudflare 的模板配置及专用依赖；保留 Vinext、React RSC 的实际构建依赖与 `next.config.ts`。
- 将历史决策归入 `DESIGN.md`，维护流程归入 `docs/maintenance.md`，文档入口仅列当前权威资料。保留数据检查与研究证据，删除孤立覆盖快照。
- 不因文件大而机械拆分或删除，也不将 React 旧链接弹窗与可分享静态详情误判为重复功能。

## 验证与回滚

保存清理前文件清单、体积及案例/视频清单哈希；比较清理后的事实源字节，确认 285 条案例、121 段完整录像与 594 个静态页面仍保留。执行 `npm run check`、`npm run lint`、普通与 Pages 构建；验证本地开发、静态预览、双语详情、过滤、旧链接与视频。界面证据用真实桌面/手机截图，并检查控制台及文档本地链接。

三路人工审查覆盖运行时代码、依赖和文档。OCR CLI 的 `ocr llm test` 失败：现有 siliconflow provider 未配置；不写入凭据或将其宣称为已完成的自动审查。

每类删除使用显式清单并校验绝对路径属于本项目。提交后可用 `git revert` 恢复整次清理；不强推，不清理用户其他项目或本地工作资料。
